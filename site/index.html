How it chooses

One activity. This order only.

  1. 01 Manual pin

    Forces one preset until you release it. Open programs do not matter.

  2. 02 Process rule

    Highest matching priority wins. A tie keeps the first rule you saved.

  3. 03 Default preset

    Used when nothing is pinned and no running program matches.

  4. 04 Clear

    Removes the activity when no default is set.

ActivityMux controls only the presence it publishes. Discord game detection, Spotify, consoles, and other connections stay separate.

Presets

Details, a status, a timer, artwork keys, and up to two buttons. Discord’s title comes from the application name, not the name in this list.

Process rules

Pick a running program. The rule stores its process name and a priority, not the file path.

Stays local

Tray, launch at login, reconnect, and a JSON file you can export. An update check asks before it downloads.

Setup

From install to live.

No bot token. No client secret.

  1. 01

    Create a Discord application

    Create one in the Discord Developer Portal. Name it the title you want Discord to show. Upload artwork there if you want images.

  2. 02

    Paste the Application ID

    Copy it from General Information into Settings and save. A preset can use its own ID when it needs a different title.

  3. 03

    Choose when it appears

    Make a preset, then pin it, set it as the fallback, or attach it to a running program.

FAQ

The short version.

Does ActivityMux need my Discord password or token?

No. It uses a public Application ID and Discord’s local connection on this computer.

Why doesn’t Discord show my preset name?

Discord takes the title from the application you created. A different title needs a different Application ID on that preset.

Can it control Spotify or Discord’s game detection?

No. It controls only the custom presence that ActivityMux publishes.

Where does my configuration go?

Presets, rules, and the Application ID stay in a JSON file on your computer. You can export that file. Appearance stays on that computer and is not included.

How do updates work?

The app checks GitHub Releases and asks before downloading. Windows updates through the installer. Linux updates the AppImage. The .deb package does not update itself.

Why can Windows show a SmartScreen warning?

The installers are unsigned. The source and the build workflow are public.
